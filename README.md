# design-diff

Figma から書き出したデザイン画像を、ローカル開発中のページに URL ごとに自動で重ねて表示するツールです。画像を案件のフォルダに置いておけば、ページを開くだけで対応する画像が重なり、ずれを確認できます。

画像の読み込みは Chrome 拡張が行うので、案件の HTML・テーマ・ビルド結果にコードを入れる必要はありません。Vite・WordPress・静的 HTML のどれでも同じ手順で使えます。

```
Chrome 拡張（extension/）
  └ ページを開くと CLI に問い合わせ、対応する画像があれば重ねる
CLI（design-diff serve）
  └ 案件の design-diff/ フォルダから、URL と画像の対応・画像・倍率と位置を配信する
```

必要なもの: Node.js 20 以上、Chrome。実行時の依存パッケージはありません。

## 最初の準備（1 回だけ）

このリポジトリを自分の GitHub アカウントにフォークして使います。npm には公開していません。

フォークしておくと、対応するドメインや CLI のポートなど、拡張のファイルを書き換える設定を自分のフォークにコミットしておけます（[対応するドメイン](#対応するドメイン)、[設定ファイル](#設定ファイル)を参照）。

### 1. フォークする

GitHub でこのリポジトリ（[t-izumii/design-diff](https://github.com/t-izumii/design-diff)）を開き、右上の「Fork」を押して自分のアカウントにコピーします。以下の `<ユーザー名>` は、自分の GitHub のユーザー名に置き換えてください。

### 2. CLI をインストールする

使い方に合わせて、どちらかの方法を選びます。

**そのまま使う場合**は、フォークから直接インストールします。

```sh
npm install -g github:<ユーザー名>/design-diff
design-diff --help        # 使い方が表示されれば完了
```

フォークを非公開にしている場合は、GitHub に SSH で接続できる状態にしてから、`npm install -g git+ssh://git@github.com/<ユーザー名>/design-diff.git` でインストールします。

**設定を書き換えて使う場合**は、フォークを clone してリンクします。clone したフォルダのファイルを書き換えると、すぐ反映されます。

```sh
git clone https://github.com/<ユーザー名>/design-diff.git
cd design-diff
npm link
design-diff --help        # 使い方が表示されれば完了
```

どちらの場合も、nodenv を使っているときはインストールのあとに `nodenv rehash` を実行しないと `command not found` になります。また、インストールは実行したときの Node の版に入るので、案件で別の版に切り替わる場合はその版でもインストールしてください。

`npx design-diff` は使わないでください。npm から同じ名前の別のパッケージを取得して実行してしまう可能性があります。

### 3. Chrome 拡張を入れる

1. `design-diff extension` を実行し、表示された拡張のフォルダの場所を確認する（clone した場合は、その中の `extension/` フォルダ）
2. `chrome://extensions` を開き、右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」で、1 のフォルダを選ぶ

### 更新・削除

元のリポジトリの更新を取り込むときは、GitHub の自分のフォークの画面で「Sync fork」を押します。clone している場合は、そのあと `git pull` も実行します。

続けて、インストールの方法に合わせて次を行い、最後に `chrome://extensions` で拡張の再読み込みボタンを押してください。押さないと古いパネルのまま動き、CLI と版が合わずに画像を読み込めないことがあります。

```sh
npm install -g github:<ユーザー名>/design-diff   # そのまま使う場合: もう一度インストールする
# clone して npm link した場合は、git pull だけで反映される
```

削除するときは、インストールの方法に合わせて次を実行します。

```sh
npm uninstall -g design-diff    # そのまま使う場合
npm unlink -g design-diff       # clone して npm link した場合
```

### このツール自体を開発する場合

clone して `npm link` した状態で開発します。URL と画像の対応付けや `images.json` の更新を変えたときは、`npm test` で自動テストを実行してください。改善を元のリポジトリに取り込んでほしい場合は、フォークから Pull Request を送ってください。

## 案件での使い方

### 1. 画像フォルダを作る

案件のルートで実行します。

```sh
design-diff init
```

`design-diff/` フォルダと設定ファイル、トップページ用の `index/` フォルダができます。

### 2. 画像を置く

`design-diff/` の中のフォルダの階層が、そのまま重ねたいページのパスになります。ホスト名やポートは見ないので、開発サーバーのポートが変わっても、`localhost` と `127.0.0.1` のどちらで開いても同じ画像が重なります。

```
design-diff/
  design-diff.config.json   ← CLI の設定
  images.json               ← 画像ごとの倍率と位置（自動で更新される）
  index/                    ← トップページ（/）
    TOP.png                 ← ファイル名は Figma の書き出し名のままでよい
    TOP_メニュー展開.png     ← 1 つのページに何枚でも置ける
  about/
    About.png               ← /about に一致
  news/
    News.png                ← 一覧ページ（/news）
    _slug/                  ← "_" で始まるフォルダは 1 階層分のワイルドカード
      記事詳細.png           ← /news/任意の記事 に一致
    special/
      Special.png           ← /news/special はこちらが優先される
```

| 置き方 | 決まり |
| --- | --- |
| トップページ | `index` フォルダに置く。`design-diff/` の直下に置いた画像は無視される |
| 下層ページ | `/about`・`/about/`・`/about.html`・`/about/index.html` は同じページとして扱う。フォルダ名の大文字・小文字は区別する |
| ワイルドカード | `_` で始まるフォルダは、その階層の任意の名前に一致する（`news/_slug` → `/news/xxx`）。1 階層分だけなので、`/news/2024/10` には一致しない。同じ階層に通常の名前のフォルダもあれば、そちらが優先される |
| 画像 | PNG・JPG・WebP。ファイル名は自由。同じフォルダの画像は、パネルでファイル名から選んで切り替える |

`serve` は起動したフォルダの `design-diff/` だけを配信するので、案件ごとに `serve` を起動し直してください。CLI のポートは 1 つなので、同時に配信できるのは 1 案件です。

### 3. 画像を登録する

```sh
design-diff sync
```

`images.json` に新しい画像の項目が追加され、なくなった画像の項目は削除されます。すでにある項目の値は書き換えません。`sync` をしていない画像も表示はでき、パネルで倍率や位置を変えた時点で `images.json` に追加されます。

### 4. 確認する

```sh
design-diff list      # URL と画像の対応を確認する
design-diff serve     # 開発サーバーと並べて起動しておく
```

開発中のページを開くと、対応する画像があるページでは右下にパネルが出ます。画像がないページや、`serve` を止めているときは何も表示されません。

画像の追加・差し替えや `images.json` の手での編集は、ページを再読み込みすれば反映されます。`serve` の再起動は不要です。`serve` は `Ctrl + C` で止まります。

## パネルの操作

パネルは見出しと本体に分かれています。見出しのボタンは、パネルを閉じていても使えます。

見出し（左から）

| 操作 | 内容 |
| --- | --- |
| 表示（目のアイコン） | 画像の表示・非表示を切り替える。`Alt+Shift+D` でも切り替えられる |
| 反転 | 画像の色を反転して重ねる。不透明度 50% なら一致している部分が灰色になり、ずれている部分が浮き出る |
| ロック | 色が付いている（ロック中）ときは画像が動かず、矢印キーでページが普通にスクロールする。押して色を消す（ロック解除）と、矢印キーで画像が押した方向に 1px、`Shift` を押しながらだと 10px 動く。入力欄にフォーカスがあるときは、矢印キーはその欄の操作に使われる |
| 開閉 | パネルの本体を開く・閉じる |
| 見出しのドラッグ | パネルを移動する |

本体

| 操作 | 内容 |
| --- | --- |
| 画像 | 重ねる画像をファイル名で選ぶ |
| 不透明度 | 画像の濃さ |
| 倍率 | 画像の実寸（1x）を基準にした表示倍率。−／＋で 0.1 ずつ変わる。欄では 0.01 単位で入力でき、編集中に `↑`・`↓` で 0.01、`Shift+↑`・`Shift+↓` で 0.1 増減する。「1xに戻す」で元に戻る。画像は左端を基準に置かれる |
| 位置 X・Y | 画像の位置（px）。欄をクリックして編集中に `↑`・`↓` で 1px、`Shift+↑`・`Shift+↓` で 10px 増減する。「0に戻す」で 0 になる |

Figma から 2x で書き出した画像は、倍率を 0.5 にするとフレームの幅で重なります。

### 値の保存先

倍率と位置（X・Y）は画像ごとに、案件の `design-diff/images.json` へ自動で保存されます。操作が止まってから約 0.4 秒後に CLI が書き込みます。案件のフォルダに保存されるので、同じ `localhost:3000` を別の案件で使っても値は混ざりません。CLI が止まっていて保存できないときは、パネルにエラーが表示されます。

そのほかの設定（表示・反転・ロック・画像・不透明度・開閉）はページ（ホスト + パス）ごとに、パネルの位置は全ページ共通で、ブラウザの localStorage に保存されます。こちらは案件ごとには分かれません。

## コマンド

| コマンド | 内容 |
| --- | --- |
| `design-diff init` | `design-diff/` フォルダと設定ファイルを作る |
| `design-diff sync` | 画像の追加・削除を `images.json` に反映する |
| `design-diff list` | URL と画像の対応、倍率と位置を一覧表示する。設定の誤りがあれば警告を出す |
| `design-diff extension` | Chrome 拡張のフォルダの場所を表示する |
| `design-diff serve` | 画像と対応表を配信し、パネルからの保存を受け付ける |

| オプション | 内容 |
| --- | --- |
| `--dir <パス>` | 画像フォルダの場所（既定: `./design-diff`） |
| `--port <番号>` | `serve` のポート（既定: 設定ファイルの `port`、なければ 4567） |

## 設定ファイル

### design-diff.config.json

```json
{
  "port": 4567,
  "allowedHosts": []
}
```

- `port`: CLI が待ち受けるポート。確認したいページのポートではありません。変えた場合は、`extension/content.js` の `SERVER` も合わせて、拡張を再読み込みしてください
- `allowedHosts`: CLI に問い合わせてよい開発ドメインの追加分（例: `"mysite.local"`、`"*.example.dev"`）。`.local` のサイトで使う場合も、ここにドメインを書きます（[対応するドメイン](#対応するドメイン)を参照）

### images.json

```json
{
  "index/TOP.png": { "zoom": 1, "x": 0, "y": 0 },
  "index/TOP_SP@2x.png": { "zoom": 0.5, "x": 0, "y": -12 }
}
```

キーは `design-diff/` からの画像のパスです。値はパネルの操作で書き込まれますが、手で編集することもできます。編集したらページを再読み込みしてください。パネルを開いたまま値を変えると、その画像の値はパネル側の値で上書きされます。

- `zoom`: 表示倍率。画像の横幅にこの値を掛けた幅で表示する。1 なら実寸どおり
- `x`・`y`: 画像の表示位置のずれ（px）

数値でない値などを書いた場合は初期値（`zoom` は 1、位置は 0）で表示し、`design-diff list` と `design-diff sync` で警告を出します。

## 対応するドメイン

既定では `localhost`、`127.0.0.1`、`*.localhost`、`*.test` のページで動きます。WordPress の管理画面（`/wp-admin/`、`/wp-login.php`）では動きません。

`*.local` のページ（Local などで作った WordPress のサイト）で使う場合は、案件の設定ファイルの `allowedHosts` にそのドメインを書いてください。拡張の再読み込みや `serve` の再起動は要らず、ページを再読み込みすれば反映されます。書くまでのあいだは、`serve` の画面に追加を促すメッセージが出ます。

```json
{
  "port": 4567,
  "allowedHosts": ["mysite.local"]
}
```

`.local` は同じネットワークの機器も名乗れる名前なので、既定では許可していません。`"*.local"` とまとめて書くと、同じネットワークのほかの `.local` のページからも画像を読めるようになるため、案件のドメインだけを書いてください。

それ以外のドメインで使う場合は、次の 2 か所に追加して、拡張を再読み込みしてください。`manifest.json` は拡張のファイルなので、フォークを clone して書き換え、コミットしておくと更新しても消えません。

1. `extension/manifest.json` の `matches`
2. 設定ファイルの `allowedHosts`

拡張を入れていないブラウザでは、開発環境でだけ `<script src="http://localhost:4567/overlay.js"></script>` を読み込んでも動きます。

## 注意事項

### 画像の管理

デザイン画像は容量が大きいので、案件のリポジトリでは `.gitignore` に `design-diff/**/*.png` や `design-diff/**/*.jpg` を入れるか、Git LFS で管理してください。`design-diff/` ごと外すと、`images.json` の倍率と位置もチームで共有できなくなります。また、本番に公開するディレクトリの外に置いてください。

### セキュリティ

- CLI は `127.0.0.1` でだけ待ち受けるので、同じネットワークのほかの端末からは見えません
- CLI が画像や対応表を返すのは、ローカル開発のドメイン（上記と `allowedHosts`）のページから `Origin` 付きで届いたリクエストだけです。外部サイトのページからのリクエスト、`<img>` のように `Origin` の付かないリクエスト、`localhost:ポート` / `127.0.0.1:ポート` 以外の宛先へのリクエストは拒否します。外部サイトから画像や対応表を読まれたり、画像があるかを調べられたりしないようにするためです。script タグで読み込む `/overlay.js` だけは `Origin` がなくても返します（`curl` で API を確かめるときは `-H 'Origin: http://localhost'` を付けてください）
- `images.json` への書き込み（`POST /api/images`）は、同じ条件を満たすページからの JSON 形式のリクエストだけを受け付け、`design-diff/` にある画像の `zoom`・`x`・`y` だけを変更します
- `design-diff/` の外を指すシンボリックリンク（画像・`images.json`・設定ファイル）は使いません。他人から受け取ったリポジトリの `design-diff/` を通して、手元のほかのファイルを読まれたり書き換えられたりしないようにするためです。`images.json` は一時ファイルに書いてから置き換えるので、リンク先には書き込みません
- 拡張が CLI に送るのはページのオリジンとパスだけで、クエリ文字列や `#` 以降は送りません
- 許可したドメインのページは、どれも画像と対応表を読めます。そのため、同じネットワークの機器（プリンター・NAS・ほかの人の PC など）も名乗れる `*.local` は、既定では許可していません（[対応するドメイン](#対応するドメイン)を参照）
